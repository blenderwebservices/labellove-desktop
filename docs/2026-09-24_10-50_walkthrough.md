# Reporte de Diagnóstico y Entrega: Publicación de Cambios al Repositorio Remoto (Origin)

**Fecha y Hora:** 2026-09-24 10:50  
**Proyecto:** LabelLove Desktop Web  
**Estado:** 🔍 Diagnóstico Realizado • Guía de Resolución Provista  

---

## 1. Diagnóstico Técnico: ¿Por qué no se aplican los cambios a `origin`?

Al ejecutar el comando de sincronización/publicación (`git push`), el proceso se detiene o falla por los siguientes motivos técnicos comprobados:

1. **El commit local está listo pero pendiente de subir:**
   - La rama local `main` se encuentra 1 commit por delante de `origin/main`:
     ```text
     501c233 feat: introduce new job modal, preset templates, and unsaved changes confirmation with updated theme styling
     ```
   - Este commit incluye todas las mejoras desarrolladas:
     - Modal de nuevo trabajo con catálogo de plantillas Avery / Retail.
     - Detección de cambios sin guardar y diálogos de confirmación.
     - Importación de archivos Excel / CSV multi-hojas en el Data Drawer.
     - Selector de Modo Claro / Modo Oscuro / Modo Sistema.
     - Compatibilidad Node/Browser para pruebas automatizadas.

2. **El remoto está configurado vía HTTPS:**
   - `remote.origin.url = https://github.com/blenderwebservices/labellove-desktop.git`
   - Las lecturas (`fetch`, `ls-remote`) funcionan porque el repositorio es accesible públicamente.
   - Sin embargo, las escrituras (`push`) exigen autenticación ante GitHub con permisos de escritura.

3. **Inexistencia de credenciales en el llavero de macOS (`osxkeychain`):**
   - Se verificó la consulta de credenciales:
     ```bash
     security find-internet-password -s github.com
     # Retorna: SecKeychainSearchCopyNext: The specified item could not be found in the keychain. (Código 44)
     ```
   - Al no existir credenciales guardadas, Git abre un diálogo interactivo pidiendo:
     `Username for 'https://github.com':`
   - En procesos en segundo plano o extensiones de Git dentro del entorno IDE que no cuentan con un terminal TTY interactivo conectado, la orden aborta de inmediato con el error:
     ```text
     fatal: could not read Username for 'https://github.com': terminal prompts disabled
     ```

4. **Política de autenticación de GitHub:**
   - Desde agosto de 2021, GitHub eliminó el soporte de contraseñas de cuenta para operaciones de Git sobre HTTPS. Se requiere obligatoriamente un **Personal Access Token (PAT)** o una **clave SSH**.

---

## 2. ¿Es posible aplicarlos automáticamente sin intervención del usuario?

No de forma 100% autónoma, debido a las medidas de seguridad de GitHub:
- Las credenciales privadas de GitHub pertenecen al usuario y no están guardadas en el sistema.
- Un agente no puede forjar ni adivinar un token de acceso personal ni firmar con una clave SSH que aún no ha sido registrada en la cuenta `blenderwebservices`.
- Tan pronto el usuario proporcione o ingrese su token (PAT), los cambios se aplicarán instantáneamente a `origin`.

---

## 3. Secuencia Óptima de Pasos para Resolverlo

### Método 1: Personal Access Token (PAT) — *El más rápido y recomendado*

1. **Generar el Token en GitHub:**
   - Abre tu navegador e ingresa a:  
     👉 [https://github.com/settings/tokens](https://github.com/settings/tokens)
   - Haz clic en **"Generate new token"** ➔ **"Generate new token (classic)"**.
   - En **Note**, pon por ejemplo: `LabelLove Mac`.
   - En **Expiration**, elige la vigencia deseada (ej. `90 days` o `No expiration`).
   - Marca la casilla **`repo`** (Full control of private repositories).
   - Baja y haz clic en **"Generate token"**.
   - **Copia el token generado** (comienza con `ghp_...`).

2. **Aplicar los cambios y guardar la credencial:**
   Abre tu terminal en la carpeta del proyecto y ejecuta:
   ```bash
   git push origin main
   ```
   - Cuando te pida `Username for 'https://github.com':`, escribe tu usuario o email de GitHub (`blender.webservices@gmail.com`).
   - Cuando te pida `Password for 'https://...':`, **pega el token (PAT)** que acabas de copiar.
   - macOS Keychain guardará este token de forma segura, por lo que los futuros `git push` funcionarán de inmediato sin pedir credenciales.

> **💡 Atajo en un solo paso:**  
> Puedes asociar el token directamente a la URL del remoto y subir de una sola vez ejecutando:  
> ```bash
> git remote set-url origin https://TU_TOKEN_AQUI@github.com/blenderwebservices/labellove-desktop.git
> git push origin main
> ```

---

### Método 2: Autenticación por Clave SSH (Alternativa permanente)

Si prefieres no usar tokens que expiren:

1. **Generar la clave SSH en tu Mac:**
   ```bash
   ssh-keygen -t ed25519 -C "blender.webservices@gmail.com" -f ~/.ssh/id_ed25519 -N ""
   ```
2. **Copiar la clave pública al portapapeles:**
   ```bash
   pbcopy < ~/.ssh/id_ed25519.pub
   ```
3. **Agregarla a GitHub:**
   - Ve a [https://github.com/settings/ssh/new](https://github.com/settings/ssh/new).
   - En **Title** escribe: `MacBook Pro`.
   - En **Key** pega el contenido del portapapeles (`Cmd + V`).
   - Haz clic en **Add SSH key**.
4. **Cambiar el origen a SSH y publicar:**
   ```bash
   git remote set-url origin git@github.com:blenderwebservices/labellove-desktop.git
   git push -u origin main
   ```
