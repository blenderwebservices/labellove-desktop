# Walkthrough: Diagnóstico y Resolución de Disponibilidad en Herd (`labellove-desktop.test`)

**Fecha y hora:** 2026-10-16 16:27  
**Estado:** Resuelto ✅

---

## 1. Causa Raíz Identificada

El problema que impedía acceder a `http://labellove-desktop.test` se debió a una caída del servicio de procesamiento **PHP-FPM** gestionado por **Laravel Herd**, y no a un problema con el código o con Node.js.

### Evidencia Técnica en Logs:
En `/Users/franc/Library/Application Support/Herd/Log/nginx-error.log`:
```text
connect() to unix:/Users/franc/Library/Application Support/Herd/herd.sock failed (61: Connection refused) while connecting to upstream, client: 127.0.0.1, request: "GET / ...", upstream: "fastcgi://unix:/Users/franc/Library/Application Support/Herd/herd.sock:", host: "labellove-desktop.test"
```

1. **Cómo funciona Herd con sitios estáticos:**
   - Herd utiliza internamente el driver `Valet\Drivers\BasicValetDriver`.
   - Nginx pasa todas las peticiones a través de FastCGI hacia el socket de PHP (`herd.sock`), donde el script central de enrutamiento de Valet (`server.php`) determina si debe devolver el archivo estático (`index.html`, `.css`, `.js`) o ejecutar código PHP.
2. **Qué ocurrió:**
   - El socket `/Users/franc/Library/Application Support/Herd/herd.sock` (enlace simbólico a `herd84.sock`) estaba inactivo porque el proceso `php-fpm` de PHP 8.4 no estaba en ejecución.
   - Nginx recibía `Connection refused (error 61)` y respondía al navegador con un error **`502 Bad Gateway`**.
3. **Por qué falló `npm run dev`:**
   - **LabelLove Desktop** es una aplicación con arquitectura **Zero-Build** basada en **ES Modules puros** y JavaScript nativo del navegador. No contiene (ni requiere) un archivo `package.json` para su entorno de desarrollo local.
   - Al intentar `npm run dev`, npm lanzó `ENOENT: no such file or directory, open 'package.json'`.

---

## 2. Acciones Realizadas

1. **Diagnóstico de Procesos y Configuración de Herd:**
   - Verificación de procesos activos: Nginx y Dnsmasq estaban corriendo, pero `php-fpm` estaba detenido.
   - Verificación de la versión global configurada: PHP 8.4.
2. **Reinicio de Servicios:**
   - Se ejecutó `herd restart`.
   - Se reiniciaron con éxito: DNSMasq, PHP 8.4 y Nginx.
3. **Validación de Disponibilidad:**
   - `curl -IL http://labellove-desktop.test`: Retornó `HTTP/1.1 200 OK`.
   - `curl -IL http://labellove-desktop.test/styles/theme.css`: Retornó `HTTP/1.1 200 OK`.
   - `curl -IL http://labellove-desktop.test/js/app.js`: Retornó `HTTP/1.1 200 OK`.
